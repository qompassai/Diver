## Monitors won't wake after sleep

Matt's wakeup recipe (from `scripts/monitor_wakeup.sh`):

```bash
hyprctl dispatch dpms on
sleep 1
hyprctl keyword monitor DP-1,2560x1440@143.97,0x0,1
hyprctl keyword monitor DP-2,1920x1080@59.94,2560x243,1
```

- DP-1 is the primary: 2560x1440 @ 143.97 Hz, position 0x0, scale 1.
- DP-2 is the secondary: 1920x1080 @ 59.94 Hz, position 2560x243, scale 1.
- The `sleep 1` matters: the monitors need a moment after DPMS-on before they
  accept the `keyword` lines.

Note: `monitors.conf` (nwg-displays output) currently lists slightly different
positions (DP-1 at `0x526`, DP-2 at `2560x778`). The wakeup script's lines are
the canonical session layout — `hyprctl keyword monitor` applies live and
overrides the config-file values.

## After editing Hyprland config — reload with the bar

**Kill the bar first.** Matt's bar is noctalia-shell on quickshell, and
reloading Hyprland without restarting it leaves the bar dead or stale. This is
also bound to Super+F12 (`scripts/reload_desktop.sh`):

```bash
pkill quickshell
hyprctl reload
sleep 1
quickshell -c noctalia-shell
```

The trailing `quickshell -c noctalia-shell` runs detached so the bar survives
the shell exiting.

## monitors.conf is generated — never hand-edit it

`monitors.conf` is written by **nwg-displays**; its header says so:

```
# Generated by nwg-displays on 2025-12-09 at 10:49:47. Do not edit manually.
```

Never edit it by hand — a later nwg-displays run will silently overwrite the
change, and a mismatch between the file and the live layout is the usual
source of "my monitors moved" confusion. To change the layout either
regenerate the file with nwg-displays, or apply the change live with
`hyprctl keyword monitor` (see the wakeup section for the canonical lines).

## Tile/free layout toggle

Matt toggles between Hyprland's default tiling and an all-floating mode via a
symlink plus a state file. The switch: `windowrules.current_mode.conf` (a
symlink sourced from the main config) points at either
`windowrules.tile.conf` (tiling; that file carries only a comment — tiling
needs no rules) or `windowrules.free.conf` (a `float-all` windowrule plus
per-app size/float fixes), and `/tmp/hypr_mode` holds `tiled` or `free`.

- Tile: `ln -sf windowrules.tile.conf windowrules.current_mode.conf`
- Free: `ln -sf windowrules.free.conf windowrules.current_mode.conf`
- Then: `echo tiled|free > /tmp/hypr_mode` and `hyprctl reload`.

> **STALE — MUST ADAPT BEFORE USE.** `scripts/toggle_layout_mode.sh` hardcodes
> `CONFIG_DIR="/home/ac/Configs/hyprland"`, a path from a previous machine that
> does not exist on primo. Do not run it as-is and do not present
> `/home/ac/...` as a live path. Replace with
> `/home/phaedrus/.GH/dotfiles/hyprland` before use. (keybinds.conf line 8 —
> the Super+Y bind to this script — and commented lines 17 and 28 carry the
> same stale `/home/ac` prefix; the active Super+F12 reload bind on line 62
> uses `~/Configs/...` and is likewise suspect on primo.)
>
> Note: `windowrules.current_mode.conf` does not currently exist as a symlink
> in the dotfiles tree, so this toggle mechanism may not be wired into the
> live config. Verify the main hyprland.conf actually sources
> `windowrules.current_mode.conf` before assuming the toggle works.

## Diagnostics

```bash
hyprctl monitors   # connected monitors, modes, positions, focus
hyprctl clients    # all windows with class, title, workspace, floating state
```

- Black screen but session alive → suspect DPMS: run the wakeup sequence.
- Bar gone after a reload → the bar wasn't restarted: run the reload sequence.
- Launcher/clipboard/lockScreen are bar features, driven via the bar's IPC:
  `qs -c noctalia-shell ipc call launcher toggle` — if the bar is dead, these
  binds (Super+Return, Super+V, Super+Ctrl+Esc) silently do nothing.
